## 2. 关键决策

### D1 — 辅助轨闸门**不用**引擎的 `command_pattern`（本任务最容易做错的一处）

`Base.command_pattern = /^S?(#{prefixes.join('|')})/i`——**只有 `^` 没有 `$`**。它是引擎内部 `dice_command` 用的**前缀筛子**，解析失败引擎自己返回 nil 不响应。拿它当 bot 闸门会把大量普通单词放进来。实测（命令模式，非我的闸门）：

```
command_pattern.match?("hello")  → true     # 抢话
command_pattern.match?("NJ")     → true     # 裸 NJ 不是有效命令
command_pattern.match?("x3")     → true
command_pattern.match?("SOULx")  → true
```

这正是 §12 R4 要防的。故闸门改为 **`\A…\z` 整条锚定**，来源两支：

1. **反射引擎自己暴露的锚定命令正则**（`RE_JUDGE_SATZ_BATZ`、`RE_EDITION1`、`NJ_RE`、`RE_KARMAROND`…）——不是抄本，规则新增命令自动进网；
2. **自建表达式语法**（镜像 `CommonCommand` 的 `Lexer`/`AddDice::Parser`）覆盖 `2d6+3`、`2B6>=4`、`D66`、`choice[a,b]`、`C1+2` 等。

### D2 — 闸门是**语法闸**不是语义闸

语法像但引擎会返回 nil 的输入（如 `NRS`、`SB_`、`1`）**放行**，交给 T2.4 的 handler 调引擎拿结果。刻意取舍：闸门**宁可多放**（handler 能给出「引擎不接受」）也**不可误杀**（漏掷骰是直接的功能损失），而**闲聊误命中才是必须防的**。

### D3 — 排除引擎的「松散」连续判定正则

`RE_JUDGE_DICEROLL` / `RE_EX_DICEROLL` 首尾虽都锚，但**脱掉 `prefixes_pattern` 前缀闸门后会放行裸数字**（`^((?:(?:UH|[KENHU])?\d+,?)+)...$` 命中 `4`/`6`/`100`）——引擎是先过前缀筛子才轮到它。故排除，改由本模块「首项必须带难度字母」的严格版覆盖同样命令。

### D4 — 三个实现期真实 bug（均已留注释防复发）

1. **`Regexp#source` + `/x`（extended 模式）**：排版用的换行/空格被原样嵌进 `.source`，再拼进**非** `/x` 的外层正则时变成**字面空白要求** → `d6`/`C1`/`choice[a,b]` 全部失配。故表达式分支一律**单行书写**。
2. **Symbol vs String**：`constants.filter_map` 里的 `const` 是 **Symbol**，排除名单写成 `%w[...]` 会**静默永不命中**，裸数字照样进闸门。改成 `%i[...]`。
3. **`module_function` 丢失**：改写模块时被删掉，`AuxMatcher.build_pattern` 退化成私有实例方法 → `NoMethodError`。

### D5 — 含空白的形态一律静默（宁漏不抢）

引擎 `Preprocessor#trim_after_whitespace` 在**第一个空格处截断**（`"K6 [J]"` → `"K6"`，即 `K6 [J]` 等价 `K6`）。若闸门照抄该语义做前缀匹配，`2d6 roll please` 必然命中 = 抢话。故闸门要求**整条无空白**（唯一例外是 repeat 形态：引擎要求 keyword 与内容间有空格）。代价是 `2d6 + 3` 不命中（玩家写 `2d6+3` 即可），已写入代码注释。

### D6 — 辅助轨开关 fail-closed

`aux_enabled` 查询自身抛异常时按**关闭**处理：宁可漏掷一次，也不在用户已关掉辅助轨的群里继续抢话。

### D7 — 暗骰 `S` 前缀统一套在最外层

引擎把命令首字母 `S` 当暗骰标记剥掉后重跑同一套解析，故 `S` 对**任何**已支持命令成立（含双 S `SSB`）。统一在交替组外套 `s?`，不必为每条命令各写变体，也就不会漏。

### D8 — `StartHandler` 放 `router.rb` 而非 `main.rb`

`main.rb` 是**入口脚本**（加载即启动长轮询，不可被测试 `require`）。handler 放 `router.rb` 才能被单测直接覆盖，同时它演示 handler 契约：**返回 String → router 代发（带 thread 透传）**。

### D9 — slash 命令集合以 `MainMenu::ENTRIES` 为准，不另抄

两处抄本必然漂移；`Router.menu_command_names` 从 `MainMenu::ENTRIES` 现取，并有测试钉住二者一致。未注册 handler 的命令按静默策略不回复——等 T2.4 逐个填。

## 3. 闸门正确性证据（实测，非推断）

**语料**：本仓库 `test/data/*.toml` 全部 NinjaSlayer 系列确定性用例中，**引擎 `eval` 确实返回非 nil** 的 ASCII 输入 → **396 条**（即"玩家真的能掷出来的命令"）。

| 指标 | 结果 |
|---|---|
| 漏放（引擎接受但闸门不认） | **0 / 396** |
| 误放（闲聊/裸数字被认成骰式） | **0**（36 条噪声语料：hello/ok/NJ/CC/1/100/3.5/2024-10-11/`今天天气3d6怎么样`/`サツバツ`/`2d6 roll please`…） |

这两条断言已写成常驻单测（`test_gate_covers_every_engine_accepted_command` / `test_gate_rejects_chatter_and_bare_numbers`），**闸门回归当场红**。

已知且刻意接受的两处语义差异：
- `NRS` 语法合法但引擎返回 nil（`NRS@3` 才有效）→ 属 D2「语法闸」，路由过去由 handler 判。
- `K6 [J]`、`x3 hello` 等含空白形态不命中 → 属 D5「宁漏不抢」。
