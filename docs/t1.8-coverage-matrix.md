## 1. 维度定义

| 维度 | 定义 | 判定方式 |
|---|---|---|
| **正常** | 该命令面至少一条成功响应用例 | toml `output` 非空串 |
| **异常** | 该命令面至少一条「应不响应」用例 | toml `output = ""`（runner 转 nil） |
| **边界** | 越界 / 端点 / 前导零 / 钳制 / DKK 极值等语义边界 | 生成器按 min_index、datarange、sides 自动取端点 |
| **暗骰** | S 前缀形态可用（`secret = true`） | 覆盖 `prefixes_pattern` 覆写，这是 T1.7 最脆弱的接缝 |
| **多段** | 逗号多段 / `][` 多段 appendix | 仅父类 K 族与 T1.6 appendix 支持 |
| **透传** | 父类命令经 Ex 类**逐字零改动** | 生成器同时 eval 父类与 Ex，逐字比对，不符即 abort |

**n/a（多段）理由**：1版父类 `NJ/EV/AT/EL` 的正则均为 `\A(S)?NJ(\d+)DIFFICULTY_RE?\z` 形态**无逗号多段**；
天狗 1版 9 表是纯查表（单骰/双骰），**无多段语义**。这是引擎层既有形状，不是覆盖缺口——
2版 父类的 `K{x1},N{x2}` 多段形态另有 20 条用例（见 §3）。

**⚠️（边界）理由**：`EV/AT/EL` 的「边界」维度是**语义分支**而非数值端点——
① `EV` 的 `z`（攻击侧成功数）触发 `カウンターカラテ!!`；② `AT` 出 6 的个数 ≥2 触发 `サツバツ!!`；
③ `EL` 同样是出 6 计数。这三条分支在 HEAD 孪生区各有用例（`EV4[N]/2`、`AT4` 出 6×2、`EL4`），已覆盖；
本矩阵的「边界」列指**数值端点/越界**，对这三个命令不适用。

**暗骰维度的一处实测发现（重要）**：

> 1版 父类 `NJ` **只支持单 S**（`SNJ4` ✓），**不支持双 S**（`SSNJ4` ✗）；
> `EV/AT/EL` 同理。而父类 `SB` 表**支持双 S**（`SSB` ✓）——因为 `SB` 是 `TABLES` 直查路径，
> 与 `NJ_RE` 之类的 `\A(S)?...\z` 形态不同。
> **Ex 类与父类逐字一致**（`SSNJ4` 在两侧都不响应），已作为异常系钉住——
> 防的是反向风险：日后有人「顺手把双 S 修好」而让子类与父类分家。

## 4. 超类透传抽查（任务书点名的 4 条）

任务书要求抽查 `SB` / `SB@6` / `WSE` / `NRS_E4` / `UH4` 经 Ex 类与父类**逐字一致**。
实现方式不是人工比对，而是**生成器内的机械对拍**：同一条命令、同一条骰序，
父类与 Ex 各 eval 一次，文本不等即 `abort`（不出坏 toml）。

### P4 — `EDITION1_SKELETONS` 常量承重构（唯一动行为的提案）✅ 已落地

**重构前的问题**：该常量是**注释旁证**而非行为开关——`proc_edition1_table` 只有一条代码路径（恒不钳制），
把它从 `:no_clamp` 改成 `:clamp`，运行时行为**一点不变**、全部测试照样绿。即「选型」与「行为」之间没有强制关联，是一张假账。

**重构后**：`proc_edition1_table` 按 `EDITION1_SKELETONS.fetch(key)` 分发：

```
skeleton = EDITION1_SKELETONS.fetch(key)
body = case skeleton
       when :no_clamp then items[sum - min_index]
       when :clamp    then EDITION1_DATARANGE.fetch(key) … # 本批不可达
       else raise ArgumentError, "…骨架选型未知…"
       end
```

`:clamp` 分支**刻意 fetch 一个不存在的常量** `EDITION1_DATARANGE` ——
「翻了选型却忘了补 datarange」必须当场 `KeyError`，绝不降级成假行为。

## 6. HELP_MESSAGE 整备结构

### 6.1 结构（两个 Ex 类同形）

```
HELP_MESSAGE = parent_help + extension_help
                 ↑            ↑
    NinjaSlayer::HELP_MESSAGE   本扩展自有段
  NinjaSlayer2::HELP_MESSAGE
```

**为什么拼接而不是抄一份**：抄第二份 = 上游日后增补说明时 ours 不动 → 悄悄漂移。
拼接则父类增补自动跟着走（kimi T1.7 评审 Q5 口径）。

**为什么必须拼接**：`HELP_MESSAGE` 是**常量覆写**——Ex 类一旦自己定义，父类那段**整个消失**。
2版初版正是这个形态：`/help` 里只有天狗表，看不见 `K6` 成功判定与 `NRS` 的用法
（与 `docs/t1.2-manual-diff.md` **B8**「天狗 `tablehelp` 漏列 14/25 张表」是同一类失败）。
