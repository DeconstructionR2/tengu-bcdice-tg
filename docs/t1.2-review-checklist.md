## 0. 怎么签收

**逐表打开 JSON 路径，与 yml 对应键逐字比对**（用 `jq` 或编辑器，不要目测）：

```bash
# 1) 看 JSON 原文
jq -r '.tables["nsrs発狂"].items[]' references/extracted/tengu_tables.json

# 2) 看 yml 落盘结果（注意 \\n 是 YAML 的换行转义，属正常）
bundle exec ruby -ryaml -e 'puts YAML.load_file("i18n/NinjaSlayer2Ex/ja_jp.yml", aliases: true)["ja_jp"]["NinjaSlayer2Ex"]["table"]["NSRS"]["items"]'

# 3) 机器自检（已内置，跑一次即可全量确认）
bundle exec ruby scripts/json_to_i18n.rb   # 末尾会打印「✅ 逐字回读自检通过：21 张表」
```

**机器自检已全绿**（items/name/type 逐字与 JSON 源一致）。人工复核的重点**不是「有没有丢字」**（那已被自检覆盖），
而是这四件机器判不了的事：

| 复核项 | 看什么 | 为什么机器判不了 |
|---|---|---|
| **① 规则语义** | 出目顺序、效果数值、`datarange` 钳制是否符合规则书 | 上游有 2版/1版之分，天狗表按自己版本的规则写；机器不知哪个对 |
| **② 索引偏移** | ledger 的 `min_index` 是否与命令层实现一致（见覆盖审计 §5.1） | BCDice `items[v-times]` vs 天狗 `data[出目]` 语义差，需人确认实现选哪边 |
| **③ 归属** | 每张表放 NinjaSlayer2Ex / NinjaSlayerEx 是否正确 | 归属规则来自计划 §5，人读规则语义才能判断 |
| **④ 文本异常** | 乱码、半角/全角混排残留、markdown 未闭合、URL 指向失效 | 原文本身就有的问题（如 `：` 重复、破折号混用）机器不会报错但会误导 |

**签收方式**：把每行的 `pending` 改成 `✅`（或 `⚠ + 问题描述`），并在本文件末尾的「签收记录」追加一行。

## 2. 已知的文本异常（源自上游，非转换引入）

以下问题**在钉版快照原文中就存在**，转换管线逐字保留（这是保真要求），但复核时值得记录：

1. **`ソーマトリコール_1` 第 2 条与第 12 条**：URL 前有重复冒号 `参照すること：：https://...`（原文双 `：：`）。
2. **全角/半角混排**：1版表大量使用全角数字（`【体力】−２`、`３マス`），2版表用半角（`3マス`）。这是**版本间的真实差异**，非转换错误。
3. **markdown 加粗标记**：1版表用 `**…**：`，2版表用 `**…**`。两种都是合法 markdown，呈现差异。
4. **`#/nd NSRS発狂,d`**：1版 `生い立ち_1` 与 `NSRS発狂` 文本中**引用了天狗自己的日文命令**（反引号内），本项目纯 ASCII 定案后这些引用会失效——**建议在 T1.3~T1.7 命令实现时改写为 ASCII 命令名**（属于文本编辑，需在复核时一并拍板）。
5. **`ジツ拡張サイバネ暴走_1` 的 dice 映射**：源码有 10 个骰型别名（`1d` / `d+1` / `1d6+1` 等），其中 `d`、`d+1` 单骰字面量与 `1d6` 语义重复——疑似历史遗留，1版上游 `returnDice` 注释代码证实是刻意保留的兼容别名。
