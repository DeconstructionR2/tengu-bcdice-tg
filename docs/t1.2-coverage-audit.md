## 5. ⚠ 移植期必须知道的语义陷阱（比对后才暴露的）

### 5.1 索引偏移：天狗与 BCDice 不同

| | 天狗 | BCDice |
|---|---|---|
| 查找 | `data[sumall]`（**绝对**出目索引） | `items[value - @times]`（**相对**） |

- **1..N 的 1d6 表**：两者一致（offset 1 == times 1）→ 可直接 `Table.from_i18n`
- **2d6 表（data 2..12）**：两者**恰好一致**（offset 2 == times 2）→ 可直接用
- **含 `+1` 的骰型（如 NSRS 的 `c=1d6+1`，出目 2..7）**：天狗 `data[2]` = `items[0]`；BCDice `1D6` 会算成 `items[1]` → **错位一格**

→ 10 张多骰型表（NSRS / KRS / KRZ / KRA / KRO / KRY / JITSB / KRM）**不能无条件用 `Table.from_i18n`**。
ledger 的 `dice_offsets` 字段已逐骰型登记 `min_sum` / `items_offset`，T1.3~T1.7 按它实现即可。

### 5.2 `type` 只表达默认骰型 `a`

天狗默认路径 `diceKind = temp[1] ? temp[1] : "a"`，不给 `,快捷键` 时走 `a`。故 yml 的 `type` 一律 = `a` 骰型（`1d3+x` → `1D3`，`+x` 是运行期補正不进 type）。
其余 `,b / ,c / ,d` 靠命令层分发 + `datarange` 钳制（`NJDiscordReply.addTableOutput` 的钳制语义：超界取 `data[datarange.max/min]`）。

### 5.3 `datarange` 不进 yml 结构

BCDice `DiceTable::Table` 不读 `datarange`；塞进 yml 会误导。已只记入 ledger，T1.4 的命令层实现钳制。

## 5.4 保真锚点的**幂等性**（可复现性）保证

保真锚点 `tengu_tables.json` 必须**逐字节可复现**——否则每次重跑都产生 diff，无法用于回归比对。
为此提取脚本做了三处处理：

1. **`Math.random()` 固定种子**：天狗 `Dice#diceRoll` / `replyErrorMessage()` 都用 `Math.random()`，
   直接取样会让 JSON 每次不同 → 脚本在 `extractWasshoi()` 内装 xorshift 确定性 RNG（种子 `0x5eed1234`）。
2. **错误彩蛋改全量 dump**：初稿只存 `replyErrorMessage()` 的单条 sample（随机），改为
   **全量 dump 56 条字面量**，并加**条数交叉校验**（字面量正则命中数必须 == 行首计数 56，否则抛错）。
   > 该校验在开发中真的抓到过一次 bug：`nd_errormessage.js` 末条目**无尾逗号**，
   > 原正则 `'(.*)',` 只命中 55/56 条 → 已修正为 `'(.*?)',?`。
3. **行号锚点用大括号深度追踪**：初稿按行首正则找收尾，锚点会截在嵌套对象的内部 `},` 上
   （如 `ジツ拡張サイバネ暴走_1` 原记 314-326，实为 314-336）→ 改为深度计数，25 张表锚点全部复核正确。
