## 2. 天狗语义铁律 —— 逐条源码取证 + 实现落法

### ① 钳制先于索引，绝不静默 nil

**源码原文**（`references/src/TenguDiceBot/TenguDiceBot/tengu_dice/NJDiscordReply.js:91-95`）：

```js
if (diceroll.isTableAdditionValue) {
    //可変値を使うテーブルで可変値のダイスロールを行い、結果がデータのレンジ外だった場合は、レンジ内の最も近い値を結果として使用する。
    if (checkDataTable.datarange.max < diceroll.sumall) tableString = checkDataTable.data[checkDataTable.datarange.max];
    else if (checkDataTable.datarange.min > diceroll.sumall) tableString = checkDataTable.data[checkDataTable.datarange.min];
    else tableString = checkDataTable.data[diceroll.sumall];
}
```

**落法**（`game_systems/NinjaSlayer2Ex.rb#proc_karmarond`）：

```ruby
clamped = sum.clamp(range[:min], range[:max])
items = translate("NinjaSlayer2Ex.table.#{school}.items")
body = items[clamped - KARMAROND_TABLE_MIN_INDEX]
body = items.first if body.nil?   # yml 被手工改动长度失配时兜底成端点项，仍不返回 nil
```

**与 T1.3 NSRS 的关键差异（预警项已处置）**：NSRS 的 `return nil if body.nil?` 守卫在本族**不适用**（NSRS 无 datarange，出目理论不可越界）。本族复用其骨架时已改掉：越界→钳制→取端点项，`body.nil?` 兜底也落到 `items.first` 而非 nil。`proc_ex_command` 的注释已同步澄清「出目越界的处理逐命令不同」。

**输出形态决策**（任务书要求「钳制发生时明示」）：天狗的钳制是**静默**的（只取端点项、不提示）。我们加标注 `(raw→clamped)（クランプ）`——既标出原始出目（玩家能看出掷了多少+补了多少），也标出钳制后的实际索引（便于逐条对照 yml 核验）。**语义零改动**，只是多告诉玩家一眼。形态与 T1.3 惯例对齐：`表名(骰型) ＞ (出目) ＞ 文本`。

### ② +x 解析：floor、负数合法、非数字→0

**源码原文**（`classes/SearchTableDiceroll.js:checkTable`）：

```js
if (/\+x/.test(diceStr)) {
    if (additionValue && !Number.isNaN(Number(additionValue))) {
        if (Number(additionValue) >= 0) diceStr = diceStr.replace("+x", "+" + Math.floor(Number(additionValue)));
        else                          diceStr = diceStr.replace("+x", Math.floor(Number(additionValue)));
    }
    else diceStr = diceStr.replace("+x", "");
    this.isTableAdditionValue = true;
}
```

**落法**：`addition = addition_s.nil? ? 0 : addition_s.to_f.floor`（`String#to_f` 对合法数字串与 `Number()` 语义等价，且 floor 由 `.floor` 显式给出）。

**一处刻意收紧（偏离天狗，已记录）**：天狗对 `KRS_A@abc` 这类非数字補正会 `replace("+x","")` 即**当 0 处理并照常掷骰**。我们让 `@` 后必须匹配数字串，非数字形态直接不响应——避免用户打错时被静默当成裸掷骰。天狗该行为不是有意设计（只是 `Number.isNaN` 分支的副产物），且我们的命令是纯 ASCII 正则语法，无兼容包袱。

### ③ 带 @ 補正必须显式 _X（实现期实测踩中并修正）

**天狗规则原文**（`tengu_dice/tablehelp.js` 第 3 節）：

> 補正値が省略された場合は0とみなします。**補正値を指定するときにはショートカットを省略できません**。

**踩坑实录**：初版正则写成 `(?:_([ABCD]))?(?:@(-?\d+))?` 的**可省略嵌套**形态，结果 `KRS@-1` 意外通过了（`Optional(Shortcut) + Optional(Correction)` 两段都可选时，只要 `@` 段存在就能匹配）——实测输出：

```
KRS@-1  →  "ソウカイヤカルマロンダリング(1D3) ＞ (0)（クランプ） ＞ …"   ← 错！应不响应
```

**修正**：改为两个**互斥**分支，`@` 只挂在第一个分支上：

```ruby
RE_KARMAROND = /^(KRS|KRZ|KRA|KRO|KRY)(?:_([ABCD])@([+-]?\d+(?:\.\d+)?)|(?:_([ABCD]))?)$/i
#                    ↑ 带@必须显式_        ↑不带@：_X 或全裸
```

修正后实测：`KRS@-1` → NO RESPONSE，`KRS_A@-1` → 正常响应。

### ④ `d3+3+x` 的真实语义（Node 实测钉版，非推断）

ledger 把 4 派阀的 D 骰型登记为源字面量 `d3+3+x`（**没有前导 1**）。这个隐式写法在 JS 侧如何求值，直接 `require` 钉版快照跑了一遍（`classes/dice.js` + `classes/diceroll.js`）：

```
new Dice("d3")   → { ok: true,  tranced: "1d3", sum: <骰面> }
"d3+3".split(/\+/) → ["d3", "3"]
  → "d3" 走 die 分支（补 1 → 1d3），"3" 走 NUMBER_ONLY 分支 → 纯常量 3
  ⇒ 实际 = 1 颗 3 面骰 + 常量 3，可达域 4..6
```

（对照：`new Dice("d3+3")` 直接调用会抛 `not nDm`——因为 `+` 拆分发生在 `diceroll.js` 而非 `dice.js` 内；拆分后每段单独构造都合法。）

**落法**：`times=1, sides=3, bonus=3`，展示标记 `"1D3+3"`。与 ledger `dice_ranges: {base: 1d3, min_sum: 4, max_sum: 6}` 逐位吻合。

### ⑤ 索引恒为 items[clamp(sum) - min_index]

五表 `min_index` 均为 1（ledger 逐表登记）。实现取 `items[clamped - KARMAROND_TABLE_MIN_INDEX]`，常量 `KARMAROND_TABLE_MIN_INDEX = 1`，且生成器启动时断言 `五表 min_index 不唯一` → 直接 abort（防将来某表登记漂移）。

### ⑥ 输出形态（表名取自 yml，不在代码里手写日文）

复用 T1.3 的 `nsrs_table_label` 同解：yml 的 `name` 形如 `ソウカイヤカルマロンダリング(1D3) ＞ `，其中 `(1D3)` 只是**默认骰型 a** 的标记（ledger `roll_note` 明确），B/C/D 实际掷 1D6/1D6+1/2D6，直接用 name 会标错（假信息）。故按第一个 `(` 截断，日文表名逐字来自 yml。

## 3. BCDice Preprocessor 三关 × `@±x` 语法的交互（逐条实测）

`lib/bcdice/preprocessor.rb` 的 `process` 顺序是 `trim_after_whitespace` → `replace_parentheses` → `change_text` → `replace_implicit_d`。对本族 15 个输入形态实测输出：

| 输入 | Preprocessor 输出 | 说明 |
|---|---|---|
| `KRS_C@2` | `KRS_C@2` | 不变 |
| `KRS_C@2 foo` | `KRS_C@2` | **第 1 关生效**：取空白前一段（正常期望行为） |
| `KRS_A@-1` | `KRS_A@-1` | 不变（负号不被改写） |
| `KRS_C@23` | `KRS_C@23` | ⚠ 源输入 `KRS_C@2(3)` 被第 2 关算成 `23`，见下 |
| `SKRS` | `SKRS` | 不变（S? 前缀保留） |
| `krs_c` | `krs_c` | 不变（大小写在 regex `/i` 处理） |
| `KRS_A@abc` | `KRS_A@abc` | 不变 |
| `KRS_D` / `KRO_D` | 不变 | **第 3 关不触发**（见下） |

**逐关结论**：

1. **`trim_after_whitespace`** — 正常使用（尾随注释被截断），无冲突。
2. **`replace_parentheses`** — 本族命令语法**不含 `(` `)`**，正常输入永不改写。但**存在一个已知毛刺**：若用户打 `KRS_C@2(3)`，`(3)` 会被 `Arithmetic.eval` 算成 `3` 再拼接成 `KRS_C@23`（補正变成 23）→ 随即被钳制到 max=12。不崩溃、不静默错，是钳制的正常结果，但属「括号被吃掉」的意外输入路径。**不额外防御**：天狗语法里括号只作分隔符（`/nd ソウカイヤカルマロンダリング,C,-1`），天狗自己也会把 `(3)` 算进去，行为一致。
3. **`replace_implicit_d`**（`(\d+)D([^\w]|$)` → `1D6`）— 本族命令**不含 `nD` 形态**：`@` 后是纯数字，无 `D`；`KRS_D` 里的 `_D` 前是下划线不匹配 `\d+`。**实测 15 个形态无一触发，无副作用**。
4. **`change_text`** — NinjaSlayer2 未覆写，无需处理。

**结论：ASCII `@±x` 形态与 Preprocessor 三关无冲突，无需覆写 `change_text`。**

## 5. 生成器 `scripts/gen_table_toml.rb`（已入库）

### 5.1 定位

T1.3 头注承诺「通用 toml 用例生成器将于 T1.4 入库」。本脚本读 ledger + i18n yml，对指定表按「骰型 ×（min / min+1 / 典型 / max / max+1 钳制 / 负 x / 正 x）」组合机械生成用例，**output 从真实 eval 采集**（`RandomizerMock` 固定骰序驱动真实 `BCDice.eval`）。

### 5.2 幂等机制（验收硬指标）

每张表的用例包在哨兵内：

```
# >>> BEGIN GENERATED: T1.4 KARMAROND
...
# <<< END GENERATED: T1.4 KARMAROND
```

重跑时**整块替换**，哨兵外的人手写用例逐字保留 → 连跑 md5 必同。

**实测**：

```
$ md5sum test/data/NinjaSlayer2Ex.toml
c92ab32c6efa1d3843c2119da1c06cc4
$ bundle exec ruby scripts/gen_table_toml.rb && md5sum …
c92ab32c6efa1d3843c2119da1c06cc4
$ bundle exec ruby scripts/gen_table_toml.rb && md5sum …
c92ab32c6efa1d3843c2119da1c06cc4      ← 三次相同，字节幂等
```

### 5.3 三方交叉校验（生成前，不过就 abort）

生成任何用例**之前**逐条比对，任一漂移直接 abort，绝不生成「看着绿其实语义错」的用例：

1. `ledger.datarange` ↔ 代码 `KARMAROND_DATARANGE`
2. `ledger.item_count` ↔ yml `items.size`
3. `items.size` ↔ `ledger.data_index` 跨度（`max_index − min_index + 1`）
4. `ledger.dice` 表达式 ↔ 代码 `spec[:expr]`（**归一化后**比对，见下）
5. `ledger.dice_ranges.min_sum/max_sum` ↔ 代码 `bonus + [times, times×sides]` 推出的可达域
6. `ledger.min_index` 五表唯一且 == 代码常量

**校验当场抓到一个真实不一致**：`ledger.dice.d = "d3+3+x"`（天狗源字面量，无前导 1）vs 代码 `"1D3+3"`。经 §2④ 的 Node 实测确认二者语义等价（隐式 1 + 常量），故在校验器里加 `normalize_dice_expr` 归一化（补前导 1、剥 `+x`、丢末位空段）后比对——**不是放宽断言，是把两种写法归一到同一语义再比**。

- 异常系名单同样自检：若某条「本应不响应」开始响应 → abort，防名单过时后写入假用例

## 7. 偏离与意外发现

### 偏离（1 处，有意）

1. **非数字補正更严格**：`KRS_A@abc` 在天狗被当 0 处理并照常掷骰，我们让它不响应。理由见 §2②。
2. **钳制标注为新增**：天狗静默钳制，我们明示 `(raw→clamped)（クランプ）`。任务书明确要求，语义不变。
3. **`@+n` 显式正号**：天狗原文法 `,C,2` 无符号，但 `Number("+2") === 2`。计划 §6 写的是 `@±x`，我们显式允许 `+`，属**无损放宽**（不改变任何既有语义）。
4. **括号毛刺不防御**：`KRS_C@2(3)` → `KRS_C@23`。天狗同样如此（见 §3 第 2 关）。

### 意外发现（3 处）

1. **`KRS@-1` 初版误响应**：可省略嵌套正则的经典陷阱（`Optional + Optional` 两段都可选时，`@` 段可独立成立）。靠手写实测用例抓出，非生成器发现。已改为互斥分支并加回归断言。
2. **`d3+3` 的隐式 1 语义无任何文档记载**：ledger 只存源字面量 `d3+3+x`，其求值路径要 `require` 钉版快照跑 Node 才能确认。已把实测结论写进代码注释 + 本报告 §2④ + 生成器 `normalize_dice_expr` 注释。
3. **生成器的档位矩阵需要「反推補正值」**：初版只按「出目 = 目标值、補正 = 0」生成，导致 `1D3+3` 这类可达域（4..6）完全高于 `datarange.min=1` 的骰型只能产出 1 条用例（下界钳制档永远打不到）。改为从可达域边界反推所需補正后，用例数从 85 → 108，边界覆盖完整。

### 已知局限（留给后续任务）
