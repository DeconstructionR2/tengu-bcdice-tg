# T2.2 spike 报告：ephemeral 服务端实证（真机）

> 日期：2026-10-11 ｜ 执行：主代理直跑（单发探针，不够格派子代理）
> 前置：T2.1 已实证 gem 侧参数直传无阻碍（docs/t2.1-report.md §3），本 spike 只验**服务端**。

## 1. 结论

**Bot API 服务端完整接受 ephemeral 三件套，T3.1 暗骰走 gem 原生路径 + send_ephemeral 封装即可，无需 HTTParty 兜底。**
（保留 raw_api_call 作为未来新端点的保底通道，定位不变。）

- bot：@example_dice_bot（TELEGRAM_BOT_TOKEN_TEST，.env）
- 测试场：示例群（forum 超级群 `-1001234567890`）的 **test2 话题（thread 2468）**

## 4. 遗留确认项

- **客户端可见性**：服务端已接受，但用户端是否实际渲染 ephemeral 气泡（旧版客户端可能不显示，§12 R6）需用户肉眼确认一次（test2 话题内是否看到「【T2.2 spike】 ephemeral 探针」且仅本人可见）。→ 用户已确认可见后本条关闭。
- callback_query 路径的 ephemeral（`EphemeralMessageParameters.callback_query_id`，按钮回调弹窗）未单独探——T3.1 实现「公开」按钮时顺带验证。
